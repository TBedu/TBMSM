# 手机端地铁运行参数测量系统

把手机当作 IMU + 磁力计 + GNSS 组合导航终端，利用地铁「站站停」的特点做零速修正（ZUPT），
利用地上段 GNSS 做绝对锚点，利用轨道中心线约束航向与横向位置，输出列车运行参数。

## 输出量

- 速度曲线（km/h）、最高速度、平均速度
- 纵向 / 垂向 / 横向加速度（已去重力、去零偏）
- 站间运行时分、站间里程、最大牵引/制动加速度
- 俯仰角、航向角、里程
- 轨迹俯视图（ENU 平面，可叠加轨道中心线）

## 算法要点

### 1. 误差状态定义

采用**全局误差**（导航系）约定 `C_true = Exp(δθ) · C_nom`，
使位置/速度/航向类观测的 H 矩阵都是常系数，避免姿态旋转带来的实现错误。

状态：`δx = [δp, δv, δθ, δb_g, δb_a]`，共 15 维。

### 2. 零速检测（地下段精度的生命线）

用 Skog 的 GLRT 统计量替代简单的模长/方差判据：

```
T_k = (1/W) Σ [ ||a_j - g·â_k||² / σa² + ||ω_j||² / σg² ]
```

静止时 T 服从 6 自由度卡方（期望 6），门限取 40 即可兼顾灵敏度与鲁棒性。
配合进入/退出迟滞（1.0 s / 0.05 s）与**速度安全阀**（估计速度 > 5 m/s 时拒绝 ZUPT），
防御「匀速平顺运行被误判为静止」这一最危险的失效模式。

### 3. 观测更新

| 观测 | 使用条件 | 作用 |
|---|---|---|
| ZUPT | GLRT 判定静止 | 速度置零，使加计零偏与部分陀螺零偏可观 |
| 重力调平 | 静止时 | 修正横滚/俯仰，加速加计零偏收敛 |
| GNSS 速度 | 有速度解 | 主约束，多普勒速度精度约 0.3 m/s |
| GNSS 航迹角 | 速度 > 3 m/s | 地上段获得绝对航向的最佳途径 |
| GNSS 位置 | 精度 < 10 m | 弱约束（σ=8 m），高程丢弃 |
| 轨道航向 | 有轨道数据 | 地下段航向的唯一可靠来源 |
| 轨道横向 | 有轨道数据 | 压制航向漂移的积分效应 |
| 站间距先验 | 到站时 | 抑制沿轨里程累计漂移 |
| 磁力计 | 三重门控通过 | 默认关闭（见下） |

所有观测都经过 **NIS 卡方检验**（99% 分位点）后才注入，异常观测直接丢弃。

**GNSS 精度门限（10 m）**：水平精度超过 10 m 时整帧丢弃，位置、速度、航迹角一律不用。
城市峡谷与地铁出入口的多径误差常达 20~50 m 且带系统性偏置，这种量级的观测一旦注入，
会把已经收敛的航向和位置重新拉偏，而它带来的信息量远小于轨道约束与 ZUPT。宁可不用。
被丢弃的帧数会记入 `summary.json` 的 `gnssRejected` 字段，实时页也会显示「已停用（丢弃 N 帧）」。

### 4. 为什么磁力计默认关闭

隧道内钢筋、牵引回流、车体铁磁会让磁场畸变到毫无意义。
更关键的是：本工程内置的 IGRF-13 只截断到 2 阶，在中国区域磁偏角误差约 2~4 度，
把磁航向当强观测会直接引入同量级的航向偏差。
因此默认 `useMagYaw = false`，磁力计只用于门控判断与初始航向。

### 5. 轨道约束是方案可行的关键

消费级 MEMS 在 90~180 s 站间运行中纯惯性推算会漂移数十米。
把状态从「三维自由位置」降维成「沿轨里程 + 横向偏差」后：

- 横向：轨道中心线已知，横向偏差直接作为观测量（σ=2 m）
- 航向：直线段 σ=2°，曲线段放宽到 8°
- 沿轨：每站 ZUPT 锚定 + 站间距先验

这样地下段只剩沿轨一维不确定性，误差不再累积。

### 6. 后向 RTS 平滑

航段短、停站锚点密集，天然适合反向平滑。
正向 ESKF 出实时结果，落地后做 RTS 平滑，航向与零偏的可观测性显著改善。
平滑节点按 10:1 抽稀保存以控制内存。

## 使用流程

1. 手机平放、屏幕朝上、**顶部朝列车前进方向**，放在地板或座椅上
2. 列车停稳时点击「开始测量」
3. 保持静止约 3 秒完成粗对准（界面有进度条）
4. 全程不要触碰手机
5. 到站后点击「停止并保存」，自动执行 RTS 平滑并跳转结果页

## 轨道数据

见 [app/src/main/assets/tracks/README.md](app/src/main/assets/tracks/README.md)。

没有轨道数据时把「启用轨道约束」关掉：速度曲线、加减速度、站间运行时分仍然可用，
但航向只有相对意义且会缓慢漂移。

### 由传感器数据自动生成轨道

没有外部线路数据时，可以在「记录」页点「生成轨道」，勾选同一线路的多次会话
（建议 2 次以上、起点相同），程序会自行算出轨道中心线：

1. 每条轨迹按里程等间隔重采样（默认 10 m）；
2. 以最长的一条为基准，其余按**起点对齐**后做长度加权融合，削弱单次解算的随机漂移；
3. 用 sin/cos 分量做圆周平均航向平滑（避免 ±π 跳变），窗口 60 m；
4. Douglas–Peucker 简化（容差 3 m），把点数压到几十个；
5. 识别停站（连续静止 > 8 s），站间距取各次会话的中位数作为先验；
6. 转回经纬度，写入应用私有目录 `files/tracks/<名称>.json`。

生成后会做合理性检查：最小曲线半径 < 150 m、折线自交距离 < 30 m 都会给出告警。
预览页显示中心线缩略图、识别到的停站数与站间距先验，确认无误再「保存并选用」。

注意：自动生成的轨道精度受限于解算轨迹本身，横向误差约数米量级，
适合作为**航向约束与横向弱约束**使用；若能从运营方拿到 CAD/GIS 中心线，仍应优先使用。

## 输出文件

每次会话在 `filesDir/sessions/<sessionId>/` 下生成：

| 文件 | 内容 |
|---|---|
| `raw/imu.csv` | 原始加计 + 陀螺（手机坐标系，100 Hz 左右） |
| `raw/mag.csv` | 原始磁力计 |
| `raw/gnss.csv` | 原始定位 |
| `track.csv` | 正向解算轨迹 |
| `track_smoothed.csv` | RTS 平滑轨迹 |
| `segments.csv` | 站间运行段统计 |
| `summary.json` | 会话总结 |

结果页「导出」按钮会把整个会话目录打包成 zip 分享出去。

## 参数标定建议

`NavParams` 中的噪声参数默认值针对典型消费级 MEMS。
若条件允许，用一段 1~2 小时静置数据做 Allan 方差标定后替换：

- `sigmaGyroNoise` —— 角度随机游走（ARW）
- `sigmaGyroBiasRw` —— 陀螺零偏不稳定性
- `sigmaAccNoise` —— 速度随机游走（VRW）
- `sigmaAccBiasRw` —— 加计零偏不稳定性

## 已知限制

- 手机必须平放。竖放时无法从重力确定前向，安装偏航误差会很大（界面会告警）
- 静止时绕重力轴的安装偏航在数学上不可观测，由 ESKF 的航向状态吸收，
  因此初始航向方差给到 (15°)²，靠首个 GNSS 运动段或轨道方向收敛
- 手持/口袋场景下人体运动会污染 ZUPT 判据，本系统不适用
- 内置磁场模型为 2 阶截断，仅用于门控，不可用于高精度磁航向
