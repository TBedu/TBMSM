# 轨道数据说明

## 目录

- `app/src/main/assets/tracks/*.json` —— 随应用打包的轨道（只读）
- 应用私有目录 `files/tracks/*.json` —— 运行期导入的轨道（可写）

两者都会被加载，按 `name` 去重时以 assets 优先。

## 文件格式

```json
{
  "name": "线路名称",
  "origin": { "lat": 39.9000, "lon": 116.4000, "alt": 0.0 },
  "points": [
    { "lat": 39.900000, "lon": 116.400000 },
    { "lat": 39.907187, "lon": 116.400000 }
  ],
  "stations": [
    { "name": "A站", "s": 0.0 },
    { "name": "B站", "s": 800.0 }
  ],
  "stationDistancePriors": [800.0]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 线路名称，界面下拉里显示 |
| `origin` | 是 | 参考原点，`points` 会转成以它为原点的 ENU 坐标 |
| `points` | 是 | 轨道中心线折线（经纬度），至少 2 个点。点越密，横向约束越准 |
| `stations` | 否 | 站台中心点，`s` 为沿轨里程（米，从 `points` 起点算起） |
| `stationDistancePriors` | 否 | 站间距先验（米），长度应为 `stations.size - 1` |

## 没有轨道数据时

把界面上的「启用轨道约束」关掉即可。此时：

- 地下段只靠零速修正（ZUPT）锚定速度，位置与航向会缓慢漂移；
- 速度曲线、加减速度、站间运行时分仍然可用（这些量不依赖绝对位置）；
- 航向只有相对意义，且会随时间缓慢转动。

## 如何获取轨道走向

1. **最准**：向地铁运营方索取线路中心线 CAD / GIS 数据，导出为经纬度折线。
2. **次优**：用 OpenStreetMap 的 railway=subway 线路数据（Overpass API 导出），
   注意 OSM 的线路是示意性的，横向精度约 5~20 m，够用。
3. **兜底**：地上段用本应用记录一次 GNSS 轨迹，导出 `track.csv`，
   把 east/north 转成经纬度后作为 `points` 使用（地下段无法这样获取）。
